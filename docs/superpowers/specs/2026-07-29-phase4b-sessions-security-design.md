# Фаза 4B — Безопасность / устройства (сессии) — дизайн

Дата: 2026-07-29

## Цель

Раздел «Безопасность · устройства» в профиле: список активных сессий (устройство, страна,
когда вошёл / когда активность), пометка текущего устройства, и возможность отозвать
отдельное устройство. Требует перехода от чисто stateless-JWT к сессиям с состоянием.

Бэкенд FastAPI (`backend/`), фронт Nuxt (`web/pages/app.vue`).

## Принятые решения (брейншторм)

- **Геолокация:** страна через заголовок Cloudflare `CF-IPCountry` (Saturn за Cloudflare).
  Только страна («Россия/Германия»), без внешних API. Город — возможное улучшение позже
  (MaxMind), сейчас вне объёма.
- **Отзыв:** список устройств + кнопка отозвать отдельное.
- **Приватность:** **сам IP НЕ храним** — только код страны + метка устройства + время.
- **Легаси-токены** (без `sid`) остаются валидными до истечения (без форс-разлогина всех).

## Модель сессий (ядро)

Новая таблица `sessions` (миграция 0005, async batch как 0004):
- `id` PK
- `user_id` FK → `users.id` **ON DELETE CASCADE**, index
- `device` String(120) — метка устройства из user-agent (напр. «Chrome · Windows»)
- `country` String(2) nullable — ISO-код страны из `CF-IPCountry` (напр. «RU»), либо NULL
- `created_at` DateTime tz — вход
- `last_seen_at` DateTime tz — последняя активность
- `revoked` Boolean default False

`users` не меняется (уже есть `token_version`).

## JWT и сессии

- В access-JWT добавляется claim **`sid`** (id сессии, int).
- `create_access_token(user_id, token_version, sid=None)` — кладёт `sid`, если передан.
- `decode_access_token` — возвращает `{'user_id','ver','sid'}` (`sid` = `payload.get("sid")`, может быть None).
- **Выпуск сессии при логине:** хелпер `_issue_session(db, user, request) -> str`:
  читает `request.headers['user-agent']` → `_device_label(...)`, `request.headers.get('CF-IPCountry')`
  (или `Cf-Ipcountry`; fallback None), создаёт `Session(user_id, device, country, created_at=now,
  last_seen_at=now)`, flush → возвращает `create_access_token(user.id, user.token_version, sid=session.id)`.
  Применяется во ВСЕХ точках выдачи сессии: `register`, `login`, `google_auth`
  (ветка существующей oauth-записи, ветка авто-связывания), `google_complete`. Там, где сейчас
  `create_access_token(user.id, user.token_version)` или `_session_out(user)` — заменяем на выпуск
  через сессию (эти функции получают `request`).
- **`get_current_user`** (в `deps.py`): decode → проверка `ver` (как сейчас) → если в токене есть
  `sid`: загрузить `Session` по id; если нет или `revoked` → 401 «Сессия недействительна»; иначе
  обновить `last_seen_at`, но **не чаще раза в ~2 минуты** (throttle: писать, только если
  `now - last_seen_at > 120s`, иначе не трогать — экономим записи). Если `sid` нет (легаси) —
  пропускаем проверку сессии (токен валиден до истечения). Возвращает `User`.
  - Чтобы список знал «текущее устройство», `get_current_user` кладёт `sid` в возвращаемого юзера
    (напр. `user._sid = sid`) ИЛИ добавляем отдельную зависимость. Проще: атрибут на объекте
    (`setattr(user, "current_sid", sid)`), эндпойнт списка его читает.

## Эндпойнты

- **`GET /auth/sessions`** (Bearer) — список НЕ отозванных сессий текущего юзера, сорт по
  `last_seen_at` desc. Элемент: `{id, device, country, country_name, created_at, last_seen_at,
  current: (id == user.current_sid)}`. `country_name` — русское название по коду (маппинг в бэке,
  fallback = код или «—»).
- **`DELETE /auth/sessions/{id}`** (Bearer) — если сессия принадлежит текущему юзеру → `revoked=True`,
  commit, 204. Иначе 404. (Отозвать можно и текущую = разлогин этого устройства.)
- **`POST /auth/logout-all`** (существует) — дополнительно помечает ВСЕ сессии юзера
  `revoked=True` (плюс существующий bump `token_version`).

## Устройство и страна (хелперы, без внешних зависимостей)

- `_device_label(ua: str) -> str`: простой парс UA — браузер (Chrome/Edge/YaBrowser/Firefox/
  Opera/Safari) + ОС (Windows/macOS/Linux/Android/iOS). Формат «Chrome · Windows». Fallback
  «Неизвестное устройство».
- `_country_name(code: str | None) -> str`: словарь кодов→рус. названий (RU→Россия, DE→Германия,
  US→США, GB→Великобритания, UA→Украина, KZ→Казахстан, BY→Беларусь, PL→Польша, FR→Франция,
  NL→Нидерланды, TR→Турция, … ~30 частых). Fallback = сам код или «—».

## Фронт (`app.vue`)

- В карточке «Аккаунт», ПЕРЕД «Выйти со всех устройств», добавить строку
  **«Безопасность · устройства»** (`data-act="devices"`).
- Клик открывает лист (переиспользуем стиль `.sheet2` из 4A): заголовок «Устройства»,
  `GET /auth/sessions`, список карточек: метка устройства, страна, «вошёл <дата>», «активно
  <относительно>», бейдж «Это устройство» для текущего; для НЕ текущих — кнопка «Выйти»
  (revoke) → `DELETE /auth/sessions/{id}` → перерисовать список. Если отозвали текущее —
  `clearSession()`.
- Относительное время — простой хелпер (сегодня/вчера/N дней назад).

## Безопасность

1. **IP не храним** — только код страны, метка устройства, метки времени. Минимум PII.
2. Сессии строго скоупятся по `user_id`: список и revoke — только свои (чужой id → 404).
3. Отозванная сессия отвергается на СЛЕДУЮЩЕМ запросе (`get_current_user` → 401).
4. `sid` — id сессии; проверка владения при revoke; перечисление чужих id ничего не даёт.
5. `last_seen` троттлится (не пишем на каждый запрос) — меньше нагрузки/износа.
6. Легаси-токены (без sid) не ломаются, живут до истечения (неделя), затем сессии у всех.

## Тестирование (pytest+SQLite)

- Логин создаёт сессию; `GET /auth/sessions` содержит её, `current=true`.
- Второй логин тем же юзером → две сессии; у второго токена своя `current`.
- `DELETE /auth/sessions/{id}` чужого юзера → 404; своей → 204, и токен той сессии → 401 на
  следующем `/auth/me`.
- `logout-all` → все сессии `revoked`, старые токены → 401.
- Легаси-токен без `sid` (собрать `create_access_token` без sid) → `/auth/me` 200 (не ломаем).
- `_device_label` парсит типовые UA; `_country_name` мапит код.
