# Регистрация и профиль ФАБУЛА — дизайн

Дата: 2026-07-29

## Цель

Достроить существующий FastAPI-бэкенд (не переписывать) до полноценной системы
аккаунтов: подтверждение почты, вход через Google, уникальный ник и рабочий
профиль. Фронт — Nuxt (`web/`), приложение — `web/pages/app.vue`.

## Принятые решения (из брейншторма)

- **Гейт верификации:** жёсткий — до подтверждения почты в приложение не пускаем.
- **Механизм подтверждения:** в письме и 6-значный код, и кнопка-ссылка (обе ведут
  к одной проверке).
- **Почтовый сервис:** Resend + свой домен (прод). Пишем провайдер-независимо
  (интерфейс `EmailSender`), dev-отправка (код в лог) для разработки.
- **Ник:** уникальный `@хендл` на весь сайт (регистронезависимо), он же
  отображаемое имя.
- **Google + существующая почта:** авто-связывание по подтверждённой Google-почте
  (добавляем Google как способ входа к тому же аккаунту, без дублей).
- **Профиль:** полный объём — реальные данные, смена ника, смена пароля, способы
  входа (почта/Google), выход, выход со всех устройств, загрузка аватара, удаление
  аккаунта. Игровые статы (тир/уровень/истории) пока плейсхолдер «скоро».
- **Сессия:** остаётся JWT в localStorage + Bearer (web и backend на разных
  доменах — так проще, куки cross-domain избыточно сложны). «Выход со всех
  устройств» — через версию токена (`token_version` в users; JWT несёт версию,
  при разлогине версия инкрементится → старые токены недействительны).

## Модель данных

`users` (расширяем):
- `id`, `email` (unique), `created_at` — как есть.
- `username` — **новое**, unique, indexed. Латиница/цифры/`_`, 3–20 симв.,
  уникальность регистронезависимая (храним как есть + сравниваем по lower).
- `password_hash` — есть, nullable (NULL = только Google).
- `email_verified` — **новое**, bool, default false. Жёсткий гейт смотрит сюда.
- `avatar_url` — **новое**, nullable.
- `token_version` — **новое**, int, default 0. Для «выхода со всех устройств».
- Поле `name` убираем/сливаем — ник и есть отображаемое имя.

`email_verifications` (новая): `user_id`, `code_hash`, `token_hash`, `expires_at`
(~30 мин), `attempts` (счётчик, антибрутфорс), `created_at`. Одна активная запись
на юзера, повторная отправка пересоздаёт.

`oauth_accounts` (новая): `user_id`, `provider` ('google'), `provider_user_id`
(Google `sub`), `created_at`. Unique (`provider`, `provider_user_id`).

Миграции — **Alembic** (сейчас `create_all`; для правок живой базы на Saturn нужны
нормальные миграции + бэкфилл `username` для существующих тестовых юзеров).

## Флоу: подтверждение почты (Фаза 2 — ждёт домен)

1. `POST /auth/register` (username, email, password) → создаём юзера
   `email_verified=false`, генерим 6-значный код + токен-ссылку, шлём письмо,
   **сессию не выдаём**.
2. Фронт показывает экран «Подтверди почту» (ввод кода) + подсказку про ссылку.
3. `POST /auth/verify` (email + code) **или** `GET /auth/verify?token=…` (ссылка) →
   ставим `email_verified=true`, выдаём JWT → в приложение.
4. `POST /auth/resend` — повторная отправка (rate-limit).
5. Антибрутфорс: лимит попыток ввода кода, срок жизни кода, троттлинг resend.

## Флоу: Google OAuth (Фаза 3 — ждёт ключи Google Cloud)

1. Кнопка «Продолжить с Google» → OAuth2 (Authorization Code + PKCE).
2. Callback: бэкенд обменивает код на профиль (email, `sub`, email_verified).
3. Ищем по `oauth_accounts(google, sub)` → есть: вход. Нет: ищем `users.email`:
   - есть и Google-почта подтверждена → **авто-связывание** (пишем `oauth_accounts`).
   - нет → создаём юзера (`email_verified=true`, пароль NULL) и просим **выбрать
     уникальный ник** (экран «создай ник» с проверкой занятости).
4. Выдаём JWT → в приложение.

## Профиль (Фаза 1 — строим сейчас)

Бэкенд-эндпойнты (все под Bearer):
- `GET /auth/me` — расширяем: `username`, `email`, `email_verified`, `created_at`,
  `avatar_url`, `providers` (['email'|'google']).
- `PATCH /auth/username` — смена ника (проверка уникальности/формата).
- `POST /auth/change-password` — смена пароля (старый+новый; для Google-only —
  «добавить пароль» без старого).
- `POST /auth/avatar` — загрузка аватара (хранилище — см. открытые вопросы).
- `POST /auth/logout` — текущая сессия (клиент чистит токен).
- `POST /auth/logout-all` — инкремент `token_version`.
- `DELETE /auth/account` — удаление аккаунта (с подтверждением на фронте).

UI (`app.vue`, экран `profile`) — по одобренному мокапу:
- Идентичность: аватар (+кнопка загрузки), `@ник`, почта + бейдж «подтверждена»,
  дата регистрации.
- Игровой блок (тир/уровень/статы) — плейсхолдер «игровое · скоро».
- Секция АККАУНТ: Никнейм (изменить), Пароль (изменить), Способы входа
  (Почта/Google), Выйти, Выйти со всех устройств.
- Секция НАСТРОЙКИ: подписка, звук, вернуться на сайт (как есть).
- Опасная зона: Удалить аккаунт.
- Глубокие действия (смена ника/пароля, удаление) — через нижние шиты/модалки.

## Провайдер почты (абстракция)

`EmailSender` (интерфейс): `send_verification(email, code, link)`. Реализации:
`DevEmailSender` (пишет в лог/консоль — dev), `ResendEmailSender` (прод). Выбор —
через env (`EMAIL_PROVIDER`). Так переезд Resend→SES позже = новая реализация +
конфиг, без правок флоу.

## Безопасность

- Пароли — argon2 (как сейчас). Коды/токены верификации храним хэшами.
- Rate-limit на register/verify/resend/login (антибрутфорс, антиспам письмами).
- JWT несёт `sub` + `token_version`; `get_current_user` сверяет версию.
- CORS уже настроен на домен web.
- Не отдаём наружу, существует ли почта (одинаковые ответы на login/resend).

## Фазирование

- **Фаза 1 (сейчас, без внешних зависимостей):** `username` + миграции; профиль-
  эндпойнты (me/username/password/logout/logout-all/delete); профиль-UI на реальных
  данных. Google в способах входа — «скоро» (кнопка неактивна до Фазы 3).
  Поскольку верификации ещё нет, в Фазе 1 `email_verified` по умолчанию `true`
  (гейта нет), бейдж показывает «подтверждена». В Фазе 2 дефолт меняется на `false`
  и включается жёсткий гейт — новые регистрации проходят подтверждение.
- **Фаза 2 (ждёт домен):** отправка писем (Resend) + флоу верификации + жёсткий
  гейт.
- **Фаза 3 (ждёт ключи Google):** Google OAuth + авто-связывание + экран «создай
  ник».
- **Аватар:** после решения по хранилищу (Фаза 1b).

## Тестирование

- Юнит: валидация ника (формат/уникальность), хэш/проверка кода, версия токена.
- Интеграционные (httpx против SQLite, как текущий smoke_test): register→verify→
  me; смена ника (занят/свободен); смена пароля; logout-all инвалидирует старый
  токен; delete.
- E2E на боевом: регистрация/вход/профиль через реальный фронт (как уже делали).

## Открытые вопросы

- **Домен** для Resend (покупка + DNS). Блокирует Фазу 2.
- **Google Cloud OAuth** client_id/secret + redirect URI. Блокирует Фазу 3.
- **Хранилище аватаров:** том на Saturn или объектное хранилище (S3-совместимое).
  Решить перед аватаром.
- Ник существующих тестовых юзеров при бэкфилле (сгенерить из email-части?).
