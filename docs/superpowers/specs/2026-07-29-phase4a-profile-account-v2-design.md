# Фаза 4A — Профиль/аккаунт v2 — дизайн

Дата: 2026-07-29

## Цель

Довести профиль и управление аккаунтом до продукта: загрузка аватара, внутренние
модалки (ник/пароль) вместо браузерных `prompt()`, фикс привязки Google, реструктура
профиля (истории/уровень/достижения на виду, настройки — за шестерёнкой), вынос выхода
в правый верх, лист настроек со звуком и размером шрифта, корректная навигация после входа.

Бэкенд FastAPI (`backend/`), фронт Nuxt (`web/`): приложение `web/pages/app.vue`
(+ `web/assets/css/app.css`), лендинг `web/pages/index.vue`.

## Принятые решения (брейншторм)

- **Объём:** только Фаза 4A. Сессии/устройства (#7) — Фаза 4B; подписки/оплата (#9) —
  Фаза 5 (в 4A только заглушка «Скоро»).
- **Аватар:** хранение в Postgres (байты), ресайз до 256×256 webp.
- **Профиль показывает:** истории + общий уровень/XP + достижения; настройки — за шестерёнкой.
- **Google после отвязки:** авто-связывание по подтверждённой почте оставляем (объяснено, не меняем).
- **«Миры» в шапке лендинга:** ведёт в приложение на экран выбора мира.
- **«Оформление»:** оставляем как «Размер шрифта чтения» (S/M/L).

## Важный нюанс: демо-данные

Уровень/XP/достижения/список активных историй с прогрессом — **игровой прогресс, домен
Миши; в auth-бэкенде их нет**. В 4A делаем **UI** этих блоков на демо-данных (как сейчас
в app.vue). Реальные данные подтянутся, когда появится игровой бэкенд прогресса. Реально
рабочие в 4A: аватар, ник, пароль, Google, выходы, звук, размер шрифта, навигация.
См. [[fabula-future-notes]] — интерфейс историй ещё заменят.

## Бэкенд — аватар (единственное изменение бэка в 4A)

**Модель (`app/models.py`, миграция 0004):** в таблицу `users` добавить:
- `avatar_data` `LargeBinary`, nullable — байты webp (256×256).
- `avatar_updated_at` `DateTime(timezone=True)`, nullable — для cache-busting.
- `avatar_url` (уже есть) — **не используем для загрузок**; оставляем как есть (задел под
  внешние URL/соцсети). Признак «есть свой аватар» = `avatar_data is not None`.

**Зависимость:** `Pillow` в `requirements.txt`.

**Эндпойнты (Bearer):**
- `POST /auth/avatar` — принимает `multipart/form-data` файл (`UploadFile`). Валидация
  (см. Безопасность), ресайз до квадрата 256×256, перекодирование в webp, запись
  `avatar_data`+`avatar_updated_at`. Ответ: `{avatar: true, v: <updated_at ts>}`.
- `DELETE /auth/avatar` — `avatar_data=NULL`. 204.
- `GET /auth/avatar/{user_id}` — **публичный** (аватар не секрет), отдаёт webp с
  `Content-Type: image/webp`, `Cache-Control: public, max-age=300`. Если нет — 404.

**`GET /auth/me`:** в `UserOut` добавить `has_avatar: bool` (= `avatar_data is not None`)
и `avatar_v: int | None` (timestamp для cache-busting URL). Фронт строит URL
`GET /auth/avatar/{id}?v={avatar_v}`.

### Безопасность аватара (критично — приоритет пользователя)

1. **Не доверяем расширению/Content-Type.** Открываем через `PIL.Image.open`, вызываем
   `.verify()`, затем повторно открываем и ресайзим. Не-картинка → 400.
2. **Перекодируем в webp** — это уничтожает возможные полезные нагрузки/EXIF/скрипты в
   исходном файле (выходной байт-поток генерим сами).
3. **Лимит размера:** читаем не более ~3 МБ (проверка `len(bytes)`), иначе 413/400.
   Лимит и на пиксели (напр. ≤ 6000×6000 до ресайза) — защита от «pixel bomb».
4. **Auth required** на POST/DELETE. GET публичный, но отдаёт только webp-байты (никаких
   путей/файловой системы — данные из БД).
5. Никаких имён файлов/путей от пользователя — храним в БД, отдаём по `user_id`.

## Фронт — навигация и вход (#13, #12)

- **После успешного входа/регистрации** (обычная форма И Google-флоу, И экран ника
  `/auth/google/complete`): сохраняем сессию, **закрываем модалку, остаёмся на лендинге**,
  обновляем шапку в залогиненное состояние. **Убираем редирект `go()`/`location='/app'`.**
- **Шапка лендинга, залогинен:** правый кластер — **«Миры» → `/app?scr=packs`**,
  **«Профиль» → `/app?scr=profile`**, **«Продолжить» → `/app`**. Секционные якоря
  «Возможности», «Тарифы» остаются. В разлогиненном состоянии — как сейчас
  (Миры/Возможности/Тарифы + Войти + Начать).
- **`app.vue` читает `?scr=`** при загрузке: если `packs`/`profile`/`home` — открывает
  этот экран (через существующую `go(name)`), иначе дефолт `home`.
- **Убрать строку «Вернуться на сайт»** из профиля (на сайт ведёт бренд ФАБУЛА в меню).

## Фронт — профиль: реструктура (#14, #6)

Экран `[data-scr="profile"]` перестраивается (разметка + стили нейтральные, как в 4-й итерации):

- **Шапка профиля:** слева «Профиль», справа **[🚪 Выйти]** (дверь-иконка + текст,
  `data-act="logout"`) и **[⚙]** (`data-act="open-settings"`).
- **Тело (сверху вниз):**
  1. Личность: аватар (кликабелен → загрузка, значок ✎), `@ник`, почта + «подтверждена», дата.
  2. **Уровень и достижения** (демо): «Уровень N · титул», XP-бар, ряд бейджей (открытые +
     заблокированные полупрозрачные).
  3. **Активные истории** (демо, детально): обложка, название, «Глава · %», роль, время
     последней активности, тонкий прогресс-бар. Клик → открыть историю (как сейчас `data-open`).
  4. **Аккаунт** (карточка): Никнейм, Пароль, Почта (подключена), Google
     (привязан·отвязать / привязать), **Выйти со всех устройств**. (Единичный «Выйти»
     переехал в правый верх. Место под «Безопасность · устройства» — Фаза 4B.)
- **Настройки (звук/оформление/подписка) уезжают в лист за ⚙** (сейчас они были инлайн).

## Фронт — модалки аккаунта (#3, #4, #5)

Общий компонент модалки в стиле лендинг-модалки (оверлей + карточка `--surface`, инпуты,
инлайн-сообщение об ошибке, кнопки). Заменяет `prompt()/confirm()`.

- **Ник (#3):** инпут (плейсхолдер правил `3–20, латиница/цифры/_`), клиентская проверка
  `^[A-Za-z0-9_]{3,20}$`, отправка `PATCH /auth/username`. Ошибки инлайн: 409 → «Ник занят»,
  422 → «Проверь формат». Успех → тост + `loadProfile()`.
- **Пароль (#4):** поля «Текущий пароль», «Новый пароль (≥6)», «Повтор». Проверка совпадения
  и длины. `POST /auth/change-password`. Успех → тост «Пароль изменён, войдите заново» →
  `clearSession()`. **email-код — позже** (нет отправки писем; записано в память).
- **Google-привязка — фикс #5:** вместо `google.accounts.id.prompt()` (One Tap, молча
  подавляется) — открываем мини-модалку и **рисуем официальную Google-кнопку**
  (`google.accounts.id.renderButton`) в держатель внутри неё; callback с ID-токеном →
  `POST /auth/link/google`. 409 → «Уже привязан к другому», ok → тост + рефреш. Отвязка —
  как сейчас (`DELETE /auth/link/google`, 400 если нет пароля).

## Фронт — аватар (#1)

- Клик по аватару → скрытый `<input type=file accept="image/*">`. После выбора —
  **квадратный кроп по центру на клиенте** (canvas: берём меньшую сторону, центр), даунскейл
  до 256×256, кодируем в webp (`canvas.toBlob('image/webp',0.9)`), отправляем
  `POST /auth/avatar` (FormData). Успех → обновляем `<img>` на `/auth/avatar/{id}?v=…`.
- Пункт «Удалить фото» (в мини-меню аватара или рядом) → `DELETE /auth/avatar` → дефолт ♞.
- Бэк всё равно ревалидирует и ресайзит (клиентский кроп — UX, не доверие).

## Фронт — лист «Настройки» за шестерёнкой (#10, #11, #9)

Лист (bottom-sheet на мобиле / модалка на десктопе), открывается по ⚙:

- **Звук и музыка (#10):** тумблеры — **Общий звук**, **Музыка / эмбиент**, **Эффекты
  (клики/UI)**. Состояние в `localStorage` (`fabula-snd-*`), применяется к Web Audio
  (существующие `master/ambGain` + флаг для sfx). По умолчанию всё включено.
- **Оформление (#11):** «Размер шрифта чтения» — сегмент **S / M / L**. Состояние в
  `localStorage` (`fabula-fontsize`), применяется к `.reader`/`.page` (CSS-переменная
  размера). По умолчанию M.
- **Подписка и грейды (#9):** строка-заглушка «Скоро» (полноценно — Фаза 5).

## Тестирование

- **Бэкенд (pytest+SQLite):** аватар — POST валидной картинки (маленький PNG в тесте) →
  `has_avatar=true`, GET отдаёт webp; POST не-картинки → 400; POST без токена → 401; DELETE →
  `has_avatar=false`; лимит размера → 400/413. Регресс существующих 22 тестов.
- **Фронт:** сборка `npm run build`. Ручная проверка на проде (залогинен): аватар-загрузка,
  модалки ника/пароля, привязка/отвязка Google (кнопка в модалке реально появляется),
  выход из правого верха, лист настроек (звук-тумблеры, размер шрифта), навигация (после
  входа остаёмся на лендинге; Миры→app-паки, Профиль→app-профиль).
